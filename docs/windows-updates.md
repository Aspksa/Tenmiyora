# Обновление Tenmiyora на Windows

Новый запускатель **Tenmiyora-Update.bat** предназначен для обновления работающей программы из **уже подготовленного и проверенного локального каталога**. Требуются Windows PowerShell 5.1 и Python. Администраторские права не нужны при наличии разрешения на запись в каталог проекта.

## Как обновить

1. Получите обновление из доверенного источника и подготовьте отдельный каталог, содержащий `manifest.json` и файлы с теми же относительными путями. Манифест SHA-256 создаётся модулем `bootstrap/release_staging.py` (`snapshot(source, destination)`). Сам `manifest.json` не является криптографической подписью издателя.
2. Откройте `Tenmiyora-Update.bat` и укажите каталог обновления либо передайте его первым параметром (можно перетащить папку на BAT).
3. Подтвердите установку клавишей Y. Программа проверит SHA-256, штатно завершит текущую сессию, дождётся освобождения блокировки, сохранит заменяемые файлы и применит обновление.
4. Скрипт заново запустит Tenmiyora и проверит ответ `/health` нового процесса. Если проверка не пройдёт, он попытается восстановить файлы из временной резервной копии.

В пакете разрешены только `bootstrap/*`, `web/**` и `Tenmiyora.bat`. Каталоги `.runtime`, пользовательские документы, память и сохранённые API-ключи не должны включаться в пакет и не затрагиваются штатной установкой.

## Ограничения и восстановление

- Автоматическая загрузка новых версий с GitHub и кнопка обновления в веб-интерфейсе пока не реализованы.
- Установщик перезаписывает только файлы, входящие в манифест, и **не удаляет** файлы, отсутствующие в пакете.
- При ошибке остановки или занятой блокировке установка прекращается. При неудачной проверке новой версии выполняется попытка отката. Если другой процесс продолжает удерживать файлы или не удаётся завершить сервер, восстановление может потребовать ручных действий.
- При отсутствии запущенной Tenmiyora предыдущая сессия может отсутствовать; механизм всё равно проверяет блокировку лаунчера.
- Проверка SHA-256 обеспечивает целостность, но **не подтверждает автора** пакета. Используйте только доверенные официальные архивы.
- Для критически важных данных дополнительно сохраняйте отдельную резервную копию всего проекта и проверяйте обновление сначала на копии.

GitHub Actions проверяет полный сценарий на одноразовой Windows-копии: действующий BAT, локальный сервер, замену файла, повторный запуск и авторизованную проверку работоспособности.
