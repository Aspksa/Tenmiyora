# Tenmiyora

Версия **0.9.3** — восемь изолированных поведенческих экзаменов внутреннего Мозга, включённых в контроль качества поколений и CI Windows/Linux. Интерфейс не менялся.

## Лаборатория развития: 8 поведенческих экзаменов Мозга (v0.9.3)

В дополнение к уже имеющимся двенадцати статическим аудитам исходного кода введены **восемь воспроизводимых поведенческих проверок**. Каждая запускает настоящие методы Мозга в собственной временной SQLite и удаляет экспериментальные данные после завершения. Ни одно испытание не использует личную память, Cloud.ru, сетевые запросы, автоматическое переписывание кода или веса модели.

1. **Единое ядро:** все подсистемы работают с одной корректной схемой SQLite.
2. **Новые направления:** тема создаётся по двум отдельным утверждениям, но не по единственному определению.
3. **Рост веток:** новые сведения дополняют существующую ветку, а удаление одного источника не уничтожает оставшиеся.
4. **Нейросвязи:** граф строит только направленные маршруты с оригинальными доказательствами; недоказанная цепочка не становится фактом.
5. **Долговременная память:** после закрытия и повторного открытия временной базы сохраняются цитата и её местоположение.
6. **Противоречия:** расхождения в условиях помечаются как предположения, без смешивания утверждений из разных файлов.
7. **Независимость подтверждений:** одинаковые копии учитываются как одно свидетельство; прямое отрицание оспаривает связь, удалённый контраргумент отзывается; достоверность авторов не выдумывается.
8. **Безопасные синонимы:** ветки объединяются только как обратимая проекция; оригинальная память сохраняется при объединении и разъединении.

Команда запуска из каталога проекта:

```powershell
python bootstrap/brain_lab_eight.py --check --output ".runtime/quality-reports/brain-lab-eight.json"
```

При провале любого из восьми критериев команда возвращает ненулевой код, а JSON показывает конкретную ошибку. Все критерии подключены к `brain_lab.run_experiment` через метрики `lab8_*`: неудачный экзамен создаёт вердикт `failed_quality_gate` и **запрещает принятие поколения**. Восемь экзаменов также запускаются как обязательный CI на Windows и Linux.

**Ограничение:** это проверка предсказуемого поведения Мозга на искусственном наборе, **не проверка научной истинности реальных документов**, не обучение весов и не автономная эволюция кодовой базы. Экзамен никогда сам не сливает код на GitHub и не изменяет живую память пользователя. Старые контрольные поколения сравниваются только при совместимых подписях экзаменационных наборов. Веб-меню, аватар и чат не менялись.

## Лаборатория развития: 12 проверок без интерфейса (v0.9.2)

Внутренний модуль `bootstrap/brain_lab_audit.py` проверяет **исходники проекта**, а не выдаёт текст пользователя за достоверность. Он запускается без Cloud.ru, без выполнения исследуемого кода и без каких-либо изменений живой памяти или рабочих файлов. Выделены двенадцать направлений:

1. Паспорт проекта — версия, число проверенных файлов, объём и SHA-256 снимка.
2. Карта архитектуры — найденные модули, прямые зависимости, возможные циклы.
3. Обнаруженные ошибки — ошибки синтаксиса Python, нарушения локальных ссылок и рискованные конструкции.
4. Точные места проблем — путь и номер строки каждого сигнала.
5. Нарушенные связи — зависимости Python-модулей и ссылки на локальные ресурсы HTML.
6. Аномалии — повторные определения функций, полные копии исходников и пропущенные при ограничении проверки файлы.
7. Состояние Мозга — наличие обязательных модулей ядра; **не** доказательство правильности их поведения.
8. Состояние интерфейсных файлов — диагностика статических зависимостей **без изменения UI**.
9. Безопасность — лишь потенциально опасные паттерны `eval/exec`, `pickle.load` и `shell=True`; **не** полноценный аудит уязвимостей.
10. Предложения улучшений — ограниченные, декларативные рекомендации по найденным сигналам.
11. План исправлений — приоритет, точное место и рекомендуемый тест; **никаких автоматических исправлений или установки кода**.
12. Контроль тестирования — инвентаризация Python-тестов и рекомендации запуска. Отдельное поле `test_execution=not_executed` означает, что статический скан **не заявляет успешный прогон тестов**.

Ручной отчёт без изменения пользовательской SQLite:

```powershell
python bootstrap/brain_lab_audit.py --root "." --check --output ".runtime/quality-reports/brain-lab-audit.json"
```

Для внутреннего сохранения истории вызовите через существующий Python `KnowledgeStore.brain_lab_internal_audit()`, а для просмотра журнала — `KnowledgeStore.brain_lab_internal_history(limit=10)`. В SQLite таблица `brain_lab_audits` хранит снимки, новые и исчезнувшие сигналы. Повторный запуск с неизменным SHA файлов не создаёт дубликатов. Сканирование ограничено 1500 исходными файлами, 750 КБ на файл и общими 16 МБ; при превышении **отмечается неполное покрытие**, а не заявляется полноценная проверка. Папки `.runtime`, `.git`, `.venv`, `node_modules` и символические ссылки намеренно исключаются из обхода; пути и содержимое приватных файлов не записываются в отчёт.

CI Windows и Linux запускает проверку вместе с действующими тестами лаборатории. Никакой автоматической эволюции весов, безопасного исправления кода без тестов или проверенной защиты от всех атак не обещается: этот этап укрепляет **наблюдаемость** проекта, не заменяет экспертный анализ.

## Запуск

1. Скачайте проект целиком через **Code → Download ZIP** и распакуйте архив.
2. Запустите **Tenmiyora.bat** двойным щелчком.
3. После проверки Python откроется браузер. Консоль свернётся в трей рядом с часами. Если значок скрыт Windows, откройте стрелку скрытых значков.

Нужны Windows 10/11 и Windows PowerShell 5.1. Если рабочий Python **3.10 или новее** уже есть, используется он. Если Python отсутствует или не прошёл проверку, BAT автоматически скачает официальный переносной Python **3.14.10** с `www.python.org`, проверит SHA-256 и подготовит его внутри `.runtime\python`. Сторонние Python-пакеты, Node.js и права администратора не требуются. Установка Python в Windows, изменение PATH и реестра не выполняются.

Для автоматической подготовки нужен интернет только при первой загрузке (архив около 12 МБ). Архитектура сборки выбирается по Windows: x64, x86 или ARM64. Версия, URL и SHA-256 закреплены в `bootstrap/python-runtime.json`; хеши взяты с [официальной страницы выпуска](https://www.python.org/downloads/release/python-31410/). Загрузка выполняется по HTTPS с ограничением времени и одной повторной попыткой. При ошибке сети, несовпадении SHA-256 или неудачном пробном запуске установка прекращается, окно остаётся открытым с объяснением. Для повторной попытки достаточно снова запустить BAT.

Архив распаковывается во временную папку только после проверки SHA-256. Python проверяется до и после переноса в рабочую папку. Если замена существующей локальной среды не удалась, предыдущая папка восстанавливается. Завершённые и неудачные загрузки очищаются; прерванная закрытием консоли подготовка не используется при следующем запуске. Уже подготовленный рабочий Python запускается без загрузки и проверки обновлений в интернете.

Поиск рабочего Python: `.runtime\python\python.exe` → `.venv\Scripts\python.exe` → `py -3` → `python` / `python3` → реестр установленных Python. Каждый кандидат проверяется на версию и необходимые стандартные модули; неподходящие пропускаются. Embedded Python можно распаковать в `.runtime\python` без pip.

Папка проекта может находиться на другом диске или содержать пробелы, кириллицу и `!`. Запуск не зависит от текущей папки командной строки. Папка должна быть доступна для записи, архив необходимо распаковать целиком.

## Управление

Меню значка в трее: **Открыть Tenmiyora**, **Показать консоль**, **Свернуть в трей**, **Открыть журналы**, **Выход**. Двойной щелчок по значку открывает сайт. Повторный запуск BAT открывает уже работающий экземпляр. Для завершения используйте **Выход**. При недоступном трее консоль остаётся видимой.

Параметры одного BAT, отдельные ярлыки не нужны:

```bat
Tenmiyora.bat --console
Tenmiyora.bat --no-browser
Tenmiyora.bat --portable --no-browser
```

`--console` оставляет консоль видимой; `--no-browser` запускает без открытия браузера; `--portable` использует только `.runtime\python`, автоматически подготавливая его при необходимости. Параметры можно сочетать. При ошибке окно показывается и ожидает нажатия клавиши. Журналы каждого запуска и сервера находятся в `.runtime`; токен сеанса в `session.json` нельзя публиковать. Эта папка исключена из Git вместе с локальными средами Python.

## Веб-интерфейс и аватар

- Левый щелчок по Tenmiyora открывает чат. Правый щелчок открывает настройки.
- Аватар можно перетаскивать по экрану. Чат и окно настроек перемещаются отдельно за верхнюю панель.
- Аватар остаётся доступным при переходах между страницами. Перетаскивание не вызывает случайное открытие чата.
- В настройках доступны размер, прозрачность, закрепление, скрытие и мягкое движение. Скрытый аватар возвращается кнопкой в нижнем углу.
- Положение и настройки сохраняются в `.runtime/workspace.json`, поэтому не теряются при смене порта или перезапуске BAT. При изменении размера экрана окна возвращаются в видимую область.
- На сенсорном экране долгое нажатие открывает настройки; для перемещения используется один палец. `Esc` закрывает верхнее окно. При системной настройке уменьшения движения анимация отключается.

Аватар обработан через imagegen с сохранением образа и прозрачного фона. Исходная поза и хвосты не обрезаются. Сведения о файле и запрос обработки: [docs/avatar.md](docs/avatar.md).


## Мозг Tenmiyora и Диск Tenmiyora

В левом меню теперь два самостоятельных раздела:

- **Диск Tenmiyora:** папки, поиск по именам, загрузка нескольких файлов и перетаскивание, скачивание, переименование и удаление. Размер одного файла до **25 МБ**; непустые папки защищены от случайного удаления.
- **Мозг Tenmiyora:** дерево тематических веток, извлечённые фрагменты с указанием файла или чата, история пополнения и статистика. Удаление файла удаляет связанные с ним фрагменты знаний.
- **Чат:** несколько фрагментов, релевантных вопросу по совпадению слов, добавляются в контекст выбранной модели как недоверенные справочные сведения. После успешного ответа содержательные утверждения пользователя могут сохраняться в память, короткие команды, вопросы и сообщения с признаками секретов пропускаются. Ответы модели автоматически не сохраняются как факты.

Данные остаются в папке .runtime/tenmiyora-disk: оригиналы в objects, база и история — knowledge.sqlite3. Папка исключена из Git; для сохранности нужно делать её личные резервные копии. Не публикуйте .runtime — в ней также лежит незашифрованный API-ключ чата.

**Поддержка форматов:** текстовые файлы, Markdown, CSV, JSON, HTML, XML, исходный код, DOCX и XLSX извлекаются локально. Для PDF требуется дополнительный пакет pypdf, которого нет в переносной стандартной поставке. Сканированные PDF требуют OCR, которого пока нет. Изображения, видео, архивы и старые DOC/XLS можно хранить, но их содержимое не индексируется.

**Надёжное ядро v0.6.0:** локальный анализ автоматически выделяет отдельные предложения-утверждения (без выдумывания фактов), связывает их с файлом и местом в документе. Новые ветки сопоставляются с существующими по нормализованным названиям и небольшому словарю синонимов. При совместном упоминании направлений в одном документе сохраняется тематическая связь, а не утверждение о причинности. Чат теперь ищет записи через SQLite FTS5 с безопасной обработкой запроса. При недоступности FTS5 есть резервный лексический поиск. Старые данные v0.5 остаются доступными.

**Возможные противоречия:** система осторожно помечает разные цифры или отрицания в очень похожих предложениях **одного и того же файла**. Это только сигнал на проверку, не доказательство ошибки; разные условия в разных договорах не считаются противоречиями автоматически. Записи о возможных противоречиях доступны в SQLite, без новой веб-панели.

**Версии:** если загрузить файл с тем же именем в ту же папку, повторное содержимое не индексируется повторно; изменённое содержимое заменяет текущую версию, а прежние байты сохраняются в каталоге versions. Утверждения переиндексируются. Старые версии можно восстановить офлайн командой rollback-file ниже. При окончательном удалении файла его локальные прежние версии тоже удаляются (уже созданные независимые резервные ZIP-архивы не затрагиваются). Переименование файлов не переписывает старые текстовые локаторы внутри знаний; имя в источнике на момент извлечения остаётся частью истории.

**Приватность:** автоматическая отправка выдержек документа в Cloud.ru теперь **ВЫКЛЮЧЕНА по умолчанию**, даже если ключ модели настроен. Для явного разрешения можно перед запуском установить переменную окружения TENMIYORA_SEMANTIC_ENABLED=1. Дополнительно действует дневной предел TENMIYORA_SEMANTIC_DAILY_LIMIT (по умолчанию 10, допустимо от 1 до 50), один запрос на новую версию файла и очередь задач. Контакты и очевидные ключи/секреты исключаются из выборки, но проверка чувствительных сведений не гарантирует полного обезличивания — перед включением осознайте возможность отправки данных провайдеру и стоимости API. Если не включать внешнюю обработку, локальные знания и поиск продолжат работать. Дополнительно для передачи знаний из Диска **во внешний чат** требуется явное TENMIYORA_MEMORY_EXTERNAL_ENABLED=1 (по умолчанию отключено). Для локальной модели на localhost память доступна без этой переменной. При выключенном разрешении сам облачный чат продолжает работать, но автоматически найденные сведения Диска ему не передаются. Сообщения, которые вы вводите напрямую в облачный чат, по-прежнему отправляются провайдеру.

**Ограничения:** автоматическое извлечение утверждений разбивает исходный текст на предложения, поэтому сложные таблицы, юридические оговорки, неоднозначные формулировки и связь условий между предложениями могут распознаваться неполно. Лексический поиск FTS5 не заменяет эмбеддинги; качество зависит от формулировки вопроса. Анализ языковой моделью возможен только после явного разрешения и при корректном ответе JSON; неизвестные форматы и сканы не извлекаются. Мутаций весов нейросети нет.

### Резервное копирование и восстановление

Остановите Tenmiyora через трей. Затем в папке проекта выполните:

~~~console
python bootstrap/memory_backup.py backup
python bootstrap/memory_backup.py restore ПУТЬ-К-АРХИВУ.zip
python bootstrap/memory_backup.py rollback-file ID_ФАЙЛА SHA256_ВЕРСИИ
~~~

Если проект использует переносной Python, вместо python укажите путь к подготовленному интерпретатору из .runtime/python. При необходимости передайте каталог .runtime первым позиционным аргументом.

Архивы хранятся в .runtime/tenmiyora-backups, содержат согласованный снимок SQLite и файловые объекты, проверяются по SHA-256. При восстановлении прежний каталог памяти переименовывается в tenmiyora-disk-before-restore-... для аварийного возврата. Восстановление не разрешено при наличии session.json, поскольку работающий сервер может повредить заменяемую БД. Делайте копию архивов на другом носителе: хранение резервной копии только на том же диске не защищает от его поломки.

### Контроль качества памяти и поиска (v0.6.1)

Запуск из каталога проекта:

~~~console
python bootstrap/quality_eval.py --check
~~~

Команда работает **локально и без платной модели**. Она создаёт временный тестовый Диск, загружает в него вымышленные документы из tests/quality/gold.json и сверяет результат с заранее вручную размеченными утверждениями, ветками, источниками, поисковыми вопросами и предполагаемыми противоречиями. **Ваши настоящие файлы и база памяти не читаются и не изменяются.**

Результат сохраняется в .runtime/quality-reports/quality-*.json (каталог исключён из Git). В отчёте: precision/recall/F1 извлечённых утверждений, precision/recall/F1 тематических веток, проверка ссылок на источники и дубликатов, hit@3, MRR, top-1, точность результатов по документам, доля правильно отвергнутых нерелевантных запросов, precision/recall сигналов возможных противоречий. **Это метрики именно размеченных синтетических примеров и извлечения/поиска, а не достоверности произвольных документов и не качества готового ответа модели.**

Пороговые значения находятся в tests/quality/thresholds.json. Флаг --check возвращает ненулевой код при регрессии. GitHub Actions прогоняет тесты качества на Windows и Linux. Чтобы оценивать реальные юридические договоры, книги или новые направления, нужно вручную размечать дополнительные **обезличенные** примеры и расширять набор — иначе высокие баллы на маленьком корпусе создадут ложную уверенность. Не следует уменьшать пороги только ради зелёного результата. Платный смысловой классификатор через Cloud.ru в эту офлайн-оценку не входит.

### Расширенный контроль: 80 сложных документов (v0.6.2)

Чтобы получить независимый от маленького исходного набора отчёт о слабых местах мозга, выполните в папке проекта:

```console
python bootstrap/quality_stress.py --check
```

Набор из **80 детерминированно собираемых синтетических документов** находится в `tests/quality/stress_cases.py`: 10 предметных направлений × 8 разных сценариев. Тексты формируются из специально сформулированных утверждений, связанных поисковых запросов и повторяемых фрагментов. Это **не 80 настоящих экспертиз или книг**. В набор входят 20 длинных документов (основной факт расположен после большого массива текста), 20 материалов со смешанными темами, 10 документов с внутренними числовыми расхождениями, 10 с заведомо ложными утверждениями, 10 с неоднозначными формулировками и обычные материалы. Дополнительно подготовлены **100 контрольных вопросов**, из которых 20 не имеют обоснованного ответа в корпусе. Чтобы увидеть все 80 документов отдельно, выполните `python tests/quality/export_stress_cases.py`: появятся читаемые Markdown-файлы и манифест SHA-256 в `.runtime/quality-corpus`. Часть негативных вопросов содержит знакомые слова или ложные предпосылки — это диагностирует склонность поиска находить нерелевантные документы.

Проверка создаёт **отдельную временную SQLite-базу**, а не использует личный Диск. Для каждого материала оценивает: сохранён ли контрольный факт, подтверждается ли запись исходным документом, найден ли нужный документ по запросу в первых пяти результатах и на первом месте, полноту сигнала о возможных противоречиях, качество распределения по основным направлениям и поведение на запросах без ответа. Отчёт по каждому документу и каждой категории пишется в `.runtime/quality-reports/stress-*.json`. Он позволяет увидеть недочёты и ограничение текущих 160 индексируемых утверждений на длинных материалах. Наличие ложного утверждения в памяти считается **риском**, а не подтверждением истинности.

Слабые метрики не скрываются; программа **не исправляет сама алгоритмы, не переобучает модель и не меняет пользовательские данные**. В CI действуют пороги обязательной целостности и регрессии из `tests/quality/stress_floors.json`. **Критерии качества считаются отдельно**: при их нарушении отчёт содержит `quality_ready=false` и `quality_findings`, даже если технический CI зелёный. `--check` блокирует поломки самого механизма и нарушение минимальных инвариантов, `--strict` дополнительно требует достижения всех целей качества — сейчас он закономерно может завершаться ошибкой. Архивы отчётов доступны в GitHub Actions для Windows и Linux. Для реальных задач высокие показатели на синтетике не служат доказательством понимания. Эта оценка не затрагивает Cloud.ru, OCR, реальные юридические заключения и качество готового диалогового ответа. Для реальной независимой проверки позднее понадобится более разнообразный размеченный корпус, который не составлялся по тем же шаблонам, что и проверяемые правила.

### Исправления по результатам стресс-тестов (v0.6.3)

- **Длинные документы:** индексирование отдельных утверждений больше не останавливается после первых 160 записей. В пределах уже извлечённого текста (до **350 000 символов** на файл) допускается до **10 000** самостоятельных записей. В существующем дереве Мозга показатели веток основаны на новом индексе; просмотр конкретной ветки показывает до 100 последних записей, а полнотекстовый поиск использует весь индекс. Документы сверх предела извлечения, как и прежде, обрабатываются не полностью.
- **Поиск с доказательствами:** кандидат из SQLite FTS5 не считается подходящим только потому, что совпало одно слово. Поиск требует совпадения значимой части запроса в исходном фрагменте, учитывает небольшие различия окончаний, ограничивает повторы из одного документа. Для коротких запросов из 2–3 понятий допускается подтвердить их несколькими **отдельными** фрагментами одного документа. Если свидетельств недостаточно, память возвращает пустой набор вместо случайных выдержек. Это снижает риск ложной выдачи, но не делает языковую модель безошибочной.
- **Противоречия:** теперь анализируются все извлечённые утверждения; числовые расхождения в схожих условиях **одного файла** отмечаются как *возможные* противоречия. Номера служебных фрагментов не приравниваются к противоречивым условиям договора. Условия разных договоров не смешиваются. Ограничение остаётся: без глубокого анализа контекста нельзя гарантировать смысловое противоречие.
- **Явные опровержения в документах:** фразы с прямой пометкой «ошибочное утверждение» и подобной не используются как фактическое подтверждение в результатах поиска; сами источники не удаляются. Если ложность нигде не обозначена, система может считать текст релевантным, поэтому проверка реальной достоверности по-прежнему необходима.

Метрики v0.6.2 остаются сравнимыми через команду `python bootstrap/quality_stress.py --check`. Дополнительно проверяется **выдача явно ошибочных утверждений**, а не запрет на их архивное хранение. Предыдущие резервные копии SQLite совместимы; новые документы индексируются полностью до указанного лимита, а старые уже индексированные документы не переобрабатываются автоматически после обновления. Для восстановления старой памяти используйте резервную копию перед обновлением.

### Точная тематическая маршрутизация (v0.6.4)

**Проблема v0.6.3:** система могла наследовать тему с первых страниц файла и относить к ней несвязанные утверждения. Поддерживались лишь четыре основных направления; остальные документы часто попадали в «Общие знания».

**Исправление:** новый локальный классификатор `bootstrap/topic_router.py` проверяет каждое извлечённое утверждение отдельно, с небольшим прозрачным словарём характерных терминов. Он различает **Программирование, Договоры и право, Транспорт, Финансы, Энергетику, Экологию, Архитектуру, Образование, Логистику и Безопасность информации**. Если независимых свидетельств недостаточно, утверждение остаётся в «Общих знаниях». Если одно утверждение содержит достаточно убедительные признаки **двух** направлений, оно связывается с обоими, но исходный текст и источник сохраняются неизменными. Подразделы Python, Базы данных, Тестирование, Автомобили, ГСМ, Водители и другие определяются по тексту отдельного утверждения, а не по всей книге.

**Проверки:** дополнительные тесты с независимыми примерами смешанных документов, повторного использования веток, неизвестных тем и сохранения источников. На синтетическом наборе из 80 документов прежняя метрика четырёх направлений изменилась с **68,8% (v0.6.3)** до **100% (v0.6.4)**; новая метрика по всем десяти направлениям и точность исключения лишних тем — **97,5%**. Это показатели на искусственно подготовленных примерах, не гарантии для новых документов. В CI закреплены минимальные пороги, чтобы будущие изменения не ухудшали их незаметно. Стресс-отчёт сохраняет прежнюю метрику точности на четырёх старых направлениях и добавляет отдельную метрику `topic_accuracy_all_10`, а также точность исключения лишних тем `topic_precision_all_10`. Для шести новых направлений эталонная разметка находится в `tests/quality/topic_labels.json`. Эталон небольшого документа об экологии уточнён с «Общие знания» на «Экология» — **его показатели классификации не следует напрямую сравнивать с версией 0.6.3 без учёта исправленной разметки**. Не нужно вводить свои API-ключи: вся классификация работает локально.

**Ограничения:** это правила и словарь, а не понимание смысла на уровне нейросети; двусмысленные выражения и очень узкие темы иногда могут быть распределены неправильно. Утверждения из уже ранее индексированных файлов автоматически заново не классифицируются при старте, чтобы не переписывать личную память без резервного копирования; новые загрузки и изменённые версии файлов получают новую классификацию.

### Автоматический рост новых направлений (v0.6.5)

В Мозге **нет глобального ограничения в десять разрешённых направлений**: локальный модуль `bootstrap/topic_discovery.py` может создавать новые тематические корни на основе ещё незнакомого содержания документов (например, «Астрономия», «Биохимия», «Квантовая оптика»). Десять прежних направлений сохранены как базовый словарь для надёжной классификации часто встречающихся тем.

Новые корни создаются **без Cloud.ru и без отправки текста в интернет**, когда одновременно выполняются условия: имеется тематический заголовок или явное определение («X — это», «X изучает», «X исследует»); **не менее двух разных исходных утверждений** прямо содержат название темы; название проходит проверку длины, символов и запрещённых инструкций; тема не совпадает с уже известной категорией. Одиночный заголовок, одно неподтверждённое утверждение, повтор одной и той же строки и команды в документе не создают корень. В рамках одного источника допускается до 12 новых тематик для защиты от массового образования мусорных веток; **общего ограничения числа существующих направлений нет**.

Все доказательные утверждения сохраняются в `knowledge_items` с локатором и исходным файлом или сообщением чата. Таблица `discovery_evidence` сохраняет связь новой ветки с источником и контрольной суммой утверждения; реестр `discovered_topics` помечает автоматически созданные направления. При повторной загрузке изменённого документа устаревшие связи снимаются. Автоматически созданная ветка, у которой больше нет ни одного источника и которая не используется другими знаниями, может быть удалена; вручную существовавшие ветки при этом не трогаются.

**Ограничение качества:** это консервативное извлечение тематических названий по локальным правилам, не универсальное понимание каждого предмета. Если в документе нет определения или явного заголовка, либо название встретилось лишь однажды, тема может остаться в «Общих знаниях». Синонимичные названия из разных документов не всегда будут объединены без дополнительного семантического анализа: автоматически угадывать синонимы опаснее, чем сохранить две отдельные ветки. Явные инструкции, встроенные в документы, не выполняются. Предыдущие сведения и версии файлов автоматически не переписываются при обновлении. Пользовательская память остаётся локальной, если отдельно не разрешена передача сведений облачному провайдеру.

Проверки: `python -m unittest discover -s tests -p "test_open_topics.py" -v` и общий прогон качества. Веб-оформление, меню и аватар не изменялись.

### Синонимы и объединение веток без потери знаний (v0.6.6)

Синонимичные направления теперь можно **логически объединять без удаления и переписывания старых записей**. Например, при наличии двух самостоятельных утверждений из документа:

```text
«Звездоведение» — синоним «Астрономия».
«Звездоведение» также называют «Астрономия».
```

Tenmiyora сохраняет обе цитаты, их источник и связь в `topic_alias_claims` и, если минимум **две разные формулировки** подтверждают пару, создаёт обратимую запись в `topic_aliases`. Если ветки с такими именами уже существуют, в прежнем дереве «Мозг» они показываются вместе, с суммарными счётчиками. Все исходные `branches.id`, `facts`, `knowledge_items`, история и полнотекстовый индекс остаются без изменений: это **виртуальное, не физическое слияние**. При запросе содержимого общей ветки читаются обе группы записей. Новые записи с подтверждённым альтернативным именем направляются в основную ветку.

Источники связей учитываются отдельно. Повторение дословно одного и того же утверждения не считается вторым подтверждением. При удалении или замене документа удаляются его свидетельства; если осталось меньше двух разных подтверждений, объединение снимается, а ранее скрытая ветка снова видна. Система не связывает темы по простому сходству слов, случайному соседству, конструкциям с «или» и одиночным непроверенным утверждениям. **Конфликтующие или циклические объединения запрещены.**

Это консервативный локальный механизм. **Автоматические синонимы распознаются только в явных формулировках с кавычками «…»**. Например, слова «лекарство» и «препарат» без отдельного утверждения о равнозначности автоматически не объединятся; для такой задачи в будущем понадобится специализированная семантическая проверка с отдельной оценкой ошибок. Истина двух утверждений по-прежнему не гарантируется: формулировки в документе являются свидетельствами о содержимом, а не независимым доказательством научной эквивалентности.

Все операции выполняются локально без Cloud.ru и без новых контролов в веб-интерфейсе. Старая память не переиндексируется автоматически при обновлении. Тесты: `python -m unittest discover -s tests -p "test_topic_aliases.py" -v`.

### Граф проверяемых отношений знаний (v0.6.7)

При загрузке текстовых документов Мозг выделяет **только явно написанные** отношения между названными понятиями. Поддерживаются четыре направленных типа: `part_of` («является частью», «входит в состав»), `used_for` («используется для»), `depends_on` («зависит от») и `contradicts` («противоречит»). Например:

```text
«Двигатель» является частью «Автомобиль».
«Автомобиль» используется для «Перевозка грузов».
«Отчёт» зависит от «Исходные данные».
«Текущая редакция» противоречит «Предыдущая редакция».
```

Сохранённые связи доступны программно через `KnowledgeStore(...).engine.relations(term=None, limit=100)`. Каждое ребро содержит исходное предложение `evidence`, `source_type`, `source_id`, `locator`, SHA-256 исходного предложения и дату. Названия вершин нормализуются для устранения идентичных дубликатов, но направленность ребра и оригинальное написание в источнике сохраняются. В SQLite добавлены `relation_concepts` и `knowledge_relations` с индексами для локального обхода графа. Это **отдельные связи понятий**, не подмена прежних узлов тематических веток или таблицы возможных числовых противоречий.

При загрузке новой версии файла старые связи этого источника удаляются в рамках той же операции, а при окончательном удалении файла неиспользуемые вершины очищаются. Исходная память и старые ветки не переписываются. Явные связи из содержательных сообщений чата могут быть записаны локально; чат получает подходящие доказательные выдержки **только если** память доступна локальной модели либо дано прежнее явное разрешение `TENMIYORA_MEMORY_EXTERNAL_ENABLED=1` для внешней модели. Само формирование графа не требует Cloud.ru или оплачиваемых API-вызовов.

**Ограничения:** автоматически распознаются лишь однозначно сформулированные короткие предложения с понятиями в кавычках «...». Неявную причинность и реальные противоречия в разных документах система **не выдумывает**: фраза «X противоречит Y» — это зафиксированное утверждение источника, а не установленная истинность. Похожие слова и соседние разделы документа не считаются причинными отношениями. Для старых документов автоматическая ретроиндексация графа не включена, чтобы не менять накопленную память без предварительного резервного копирования. Тесты: `python -m unittest discover -s tests -p "test_knowledge_relations.py" -v`.

### Проверяемые многошаговые цепочки знаний (v0.6.8)

Мозг может искать **направленные маршруты между двумя понятиями** по ранее сохранённым фактическим формулировкам из документов:

```text
«Клапан» является частью «Насос».
«Насос» является частью «Система водоснабжения».
«Система водоснабжения» является частью «Предприятие».
```

Команда в Python (в локальном процессе с предварительно созданным объектом памяти):

```python
answer = store.engine.trace_knowledge("Клапан", "Предприятие", max_depth=3, max_paths=5)
```

Каждый найденный путь содержит отдельные шаги с типом отношения, точными цитатами, идентификаторами и локаторами источников; несколько документов, подтверждающих одно ребро, группируются **без удаления их происхождения**. Поиск направленный: обратного отношения из `A → B` не придумывает. Маршруты в ширину показывают короткие пути сначала и игнорируют циклическое повторение узлов. Максимум 4 шага, 8 путей, 100 направлений перехода на одном шаге и ограничение числа проверяемых состояний защищают от зависаний и чрезмерного потребления ресурсов. `status=incomplete` отдельно показывает случаи, когда лимиты мешают исчерпывающему обходу.

**Принцип достоверности:** `conditional_part_of_chain` — лишь *условная* композиция нескольких утверждений «является частью», при условии что все исходные формулировки верны. Любая другая смешанная цепочка получает метку `related_claims_only`: она означает только маршрут по цитатам, **не** новую причинно-следственную связь или доказанное противоречие. Отношение `contradicts` **не транзитивно**. Поле `verified=false` сохраняется даже для непосредственного утверждения — наличие цитаты не доказывает истинность документа.

Для чата автоматически предлагаются только небольшие подтверждённые цитатами цепочки, когда пользователь **явно указал два понятия в кавычках** (например, «Клапан» и «Предприятие»). Если понятия или путь не найдены, модель не получает придуманную цепочку. Как и прежде, сведения отправляются облачной модели только при отдельном разрешении `TENMIYORA_MEMORY_EXTERNAL_ENABLED=1`; локальная модель на localhost получает разрешённые сведения без внешней отправки. Никаких дополнительных API-запросов для самого поиска нет.

Выполняются независимые тесты направленности, 2–4 шагов, смешанных зависимостей, недопустимой транзитивности противоречий, циклов, ограничения глубины, повторяющихся источников, замены и удаления файлов, перезапуска памяти и вопроса для чата. Эта функция не создаёт новых сущностей и не изменяет старые данные; она использует существующий SQLite-граф. Старые документы, из которых явные отношения ещё не извлекались, не переиндексируются автоматически.

### Отношения в обычной прозе и непроверенные смысловые гипотезы (v0.6.9)

Ранее отношения между понятиями распознавались преимущественно в искусственном формате с кавычками. Теперь локальный модуль `bootstrap/natural_relations.py` дополнительно обрабатывает **короткие однозначные утверждения в обычном русском тексте**, например:

```text
Насос является частью системы водоснабжения.
Путевой лист используется для учёта пробега.
Работа насоса зависит от электропитания.
Вывод исследования противоречит исходной гипотезе.
```

Поддерживаются формы «является частью», «входит в состав», «используется для», «применяется для», «зависит от», «противоречит». Для каждого отношения сохраняются исходное предложение, локатор документа, SHA-256, идентификатор источника и `extraction_method=conservative_natural`. Старые записи сохраняют `extraction_method=explicit_quoted` благодаря совместимому обновлению SQLite. Работа полностью локальная, без новой оплаты и без автоматического сетевого запроса.

**Отказ от сомнительных связей:** отрицания («не входит»), предположения («возможно», «может»), условные и сложносочинённые фразы, инструкции из недоверенного текста и неоднозначные перечисления намеренно пропускаются. Совпадение слов в соседних предложениях никогда не создаёт ребро. Не выполняется произвольная лемматизация: «Насос» и «насоса» могут остаться разными строками, чтобы программа не подменяла доказательство догадкой о форме слова. Найденный грамматический шаблон всё ещё отражает *утверждение источника*, а не независимо подтверждённую истину.

Для более сложных абзацев **только при уже предусмотренном явном включении** `TENMIYORA_SEMANTIC_ENABLED=1` выбранная модель Cloud.ru в **том же** запросе смысловой классификации может предложить до восьми отношений. Каждое предложение проверяется: известный ID фрагмента, **дословная цитата из переданного фрагмента**, оба понятия присутствуют в цитате, допустимый тип отношения. Такие предложения сохраняются в отдельной таблице SQLite `relation_suggestions` со статусом `proposed_unverified`, а **не в `knowledge_relations`**. Они не используются для ответа чата и не становятся фактами. Программно доступны через `store.engine.relation_suggestions(file_id=None, limit=30)` для будущей процедуры проверки. При замене или удалении исходного файла они удаляются, а ответ модели для старой SHA-версии отклоняется.

**Важное ограничение:** модель может предположить неверное отношение даже при реальной цитате. Проверка цитаты подтверждает только происхождение текста, а не истинность интерпретации. Полноценное извлечение неявных причинно-следственных отношений без ошибок **не заявляется**. Не добавлялись кнопки подтверждения в интерфейс. Существующая память не переиндексируется без отдельного контролируемого запуска с резервной копией.

Контрольные тесты: `python -m unittest discover -s tests -p "test_natural_relations.py" -v` и `test_relation_suggestions.py`; они покрывают отрицания, ложные совпадения, сохранность источников, обновления файлов, старую базу, согласие на использование модели и запрет добавления её предположений в граф.

### Независимая проверка предложенных связей (v0.7.0)

Tenmiyora **не утверждает**, что предположение модели истинно только из-за найденной в документе цитаты. Для смысловых кандидатов из `relation_suggestions` новый локальный модуль `bootstrap/relation_verification.py` вычисляет три осторожных состояния:

- `proposed_unverified` — нет достаточного числа независимых, однозначных свидетельств.
- `corroborated_by_sources` — обнаружены **как минимум два разных по формулировке прямых утверждения** о том же ориентированном отношении в **двух других файлах** с различными SHA-256 и уникальными текстами свидетельств, и не обнаружено явного опровержения.
- `disputed` — найдено хотя бы одно прямое отрицание утверждаемого отношения, независимо от наличия подтверждений. Это означает **спорность**, а не доказанную ложность.

Например, смысловой кандидат `Насос → является частью → Система водоснабжения` получит отметку `corroborated_by_sources` при наличии двух других отдельных файлов с исходными формулировками «Насос является частью Система водоснабжения» и «Насос входит в состав Система водоснабжения». Если другой документ прямо сообщает «Насос не является частью Система водоснабжения», кандидат помечается как спорный. Обобщённые рассуждения, похожие слова, два экземпляра одного файла и две копии одного и того же предложения не считаются независимыми подтверждениями. Сообщения чата не участвуют в подтверждении чужих смысловых кандидатов.

Каждый проверенный результат содержит `support_count`, `counter_count`, массивы исходных подтверждений `supports` и возражений `counterarguments` с `source_id`, `evidence` и `locator`. Локальное чтение: `store.engine.relation_suggestions(file_id=None, limit=30)`. Таблица `relation_denials` хранит явные отрицания из исходного текста, а `relation_review_events` — переходы статусов. По мере загрузки, замены и удаления файлов статусы пересчитываются; после удаления подтверждения состояние может понизиться. Источник и его история сохраняются; автоматического переноса гипотезы в граф фактов **нет**. Рабочий граф содержит уже существовавшие прямые отношения из независимых документов, а не выдуманное ребро модели.

**Граница независимости:** разные локальные файлы и разные цитаты не доказывают независимость авторов/издателей и тем более научную истинность. Это лишь проверка согласованности разных документов. Кроме того, простой локальный анализ не выявляет все возможные скрытые опровержения или переформулированные синонимы; они могут остаться незамеченными. При объёме более 5000 кандидатов автоматическое массовое обновление статусов прекращается безопасно; при чтении отдельных записей основания вычисляются заново. Граф и существующие сохранённые знания не пересоздаются автоматически.

Сам механизм проверки локальный: **не вызывает Cloud.ru, не расходует API-токены и не включает передачу документов в облако**. Опциональная генерация новых смысловых кандидатов остаётся отключённой по умолчанию, включается отдельно через `TENMIYORA_SEMANTIC_ENABLED=1`. Новых кнопок и изменений интерфейса нет. Проверки: `python -m unittest discover -s tests -p "test_relation_verification.py" -v` и общая CI-проверка Windows/Linux.

### Происхождение и заимствования источников (v0.7.1)

Мозг хранит отдельный **паспорт происхождения текущей версии каждого загруженного файла** в SQLite (`file_provenance`): заявленные автор, издатель, дата документа, тип источника и исходный HTTPS-адрес. Чтобы эти поля были распознаны, их можно явно указать в начале `.txt`, `.md` или другого поддерживаемого документа:

```text
Автор: Исследователь
Издатель: Научный журнал
Дата документа: 2026-02-12
Тип источника: первичный
Источник: https://example.org/papers/report
```

Данные извлекаются **только как заявления самого документа**. Tenmiyora не посещает URL, не проверяет подписи, регистрацию издания или существование автора. `identity_verified=0` означает, что **подлинность НЕ установлена**. Если полей нет или формат сомнителен, они остаются `NULL`, а не выдумываются. Допустимы значения `первичный` / `вторичный` для типа; они отражают авторскую декларацию, а не научную оценку. Устаревшая дата (старше трёх лет) отмечается как повод проверить применимость, **не** как автоматическое доказательство ложности; отсутствие даты, автора и оригинальной публикации также видно в предупреждениях. Механизм работает локально и не добавляет сетевых запросов.

Для выявления вероятного заимствования используется **перекрытие отпечатков соседних пяти слов** в тексте с исключением полей паспорта. Сходство от 85% по отношению к более короткому тексту отмечается в таблице `file_borrowing`; методы и коэффициент перекрытия можно прочесть программно. Это **сигнал возможной копии**, не доказательство плагиата. Для производительности анализируется до 750 других файлов при загрузке и ограниченное число отпечатков; при превышении лимита или слишком коротком тексте отсутствие совпадений **не гарантирует уникальности**.

Теперь при проверке смыслового кандидата документы **группируются** по признакам общего происхождения: одинаковый заявленный автор, одинаковая исходная публикационная ссылка, сильное текстовое перекрытие; анонимные документы одного заявленного издателя также не считаются независимыми подтверждениями. Таким образом, разные файлы и разные формулировки **не обязательно дают два голоса**. Результат `store.engine.relation_suggestions(...)` дополнен полями `document_support_count` (отдельные подходящие документы), `support_count` (группы свидетельств), `source_provenance` и `source_warnings`. Прежние статусы `proposed_unverified`, `corroborated_by_sources` и `disputed` сохранены для совместимости. Даже при `corroborated_by_sources` в результате всегда `author_independence_verified=False`: это **согласованность файлов**, а не доказанная независимость авторов или достоверность. Смысловой кандидат **не превращается автоматически в ребро рабочего графа**.

Локально запросить паспорт документа можно методом `store.engine.source_provenance(file_id)`. При замене документа его метаданные и перекрытия перестраиваются, при удалении — очищаются, а статусы кандидатов пересчитываются. Ранее существующие файлы не сканируются автоматически при обновлении: отсутствие их паспортов отмечается явно, исходная память остаётся без переписывания. Улучшение не создаёт новых меню и не требует платных сервисов.

Проверки: `python -m unittest discover -s tests -p "test_source_provenance.py" -v`, полный набор CI Windows/Linux и стресс-корпус из 80 документов.

### Безопасная миграция паспортов старых документов (v0.7.2)

Новые документы получают паспорта автоматически при загрузке с v0.7.1. Для **ранее загруженных файлов**, которых эта функция ещё не касалась, предусмотрен отдельный автономный модуль `bootstrap/provenance_migration.py`. Он **не стартует автоматически**, не вызывается веб-страницей и не отправляет ничего в сеть. Сначала **полностью закройте Tenmiyora через значок в трее → Выход** и убедитесь, что локальный сервер остановлен. Затем выполните в каталоге проекта:

```powershell
python bootstrap/provenance_migration.py --workspace ".runtime" --dry-run
python bootstrap/provenance_migration.py --workspace ".runtime"
```

Если Tenmiyora использует переносной Python и отсутствует системный `python`, запускайте его в PowerShell через оператор `&`, например `& ".\.runtime\python\python.exe" bootstrap/provenance_migration.py --workspace ".runtime" --dry-run`, либо используйте другой установленный совместимый Python. Пути в кавычках поддерживают кириллицу, пробелы и расположение на любом диске. Первый вызов **только проверяет** базу, исходные файлы, их размер и SHA-256 и показывает план, ничего не изменяя. Второй запускает перенос. Не запускайте команды во время работы сервера.

**Порядок и безопасность:** (1) проверить каждый активный файл в `.runtime/tenmiyora-disk/objects` на соответствие ID, размеру и SHA-256 из SQLite; (2) проверить целостность SQLite; (3) создать **полную консистентную резервную копию SQLite через SQLite Backup API**, проверить копию и сохранить SHA-256 в манифесте; (4) одной транзакцией добавить **только отсутствующие или устаревшие паспорта** и пересчитать заимствования и статусы проверки смысловых кандидатов; (5) снова проверить целостность и подтвердить транзакцию. **Утверждения, знания, исходные документы, индексы и старые версии файлов не пересоздаются и не удаляются.** Если исходный файл отсутствует, его хеш не совпадает или возникает ошибка во время переноса, операция прекращается: при ошибке до резервирования база вообще не изменяется, при ошибке внутри транзакции — транзакция откатывается. Резервная копия сохраняется локально в `.runtime/tenmiyora-disk/backups`, она может содержать **приватные данные**, её нельзя публиковать в GitHub.

После успешного обновления повторный вызов ничего не переписывает и не создаёт новую копию. Работает без новых Python-пакетов, Cloud.ru и платных API. Требуется свободное место хотя бы под дополнительную копию SQLite, а для восстановления — ещё под страховочную копию.

**Полный откат SQLite:** остановите Tenmiyora, выберите **конкретный** файл `provenance-...-before.sqlite3` из `.runtime/tenmiyora-disk/backups` и выполните:

```powershell
python bootstrap/provenance_migration.py --workspace ".runtime" --restore ".runtime/tenmiyora-disk/backups/provenance-...-before.sqlite3" --yes
```

Восстановление проверит локальное расположение копии, SHA-256 манифеста и целостность SQLite, **сначала создаст ещё одну страховочную копию текущей базы**, затем восстановит выбранную. Это **полный** откат базы на момент резервирования: **все последующие записи в SQLite будут потеряны**, а уже созданные после этого исходные файлы могут остаться на диске без ссылок из базы. Отменяйте миграцию немедленно при возникновении проблемы, а не после продолжительной работы с новой памятью. Восстановление не предполагает внешнего сетевого доступа и не может само проверить, что сервер закрыт; убедитесь в этом перед запуском.

Для контроля предусмотрены регрессионные тесты, включая прерванную транзакцию, испорченный исходный файл, отсутствие исходного объекта, безопасный повторный запуск и восстановление старой базы. Автоматического массового переиндексирования старых утверждений **нет**: эта миграция меняет только паспорта, отпечатки заимствований и вытекающие из них статусы кандидатов.

### Нагрузочные испытания и ресурсы Мозга (v0.7.3)

Новая команда **не использует настоящие документы и не открывает личную базу**. Она создаёт изолированную временную копию структуры Tenmiyora с синтетическими документами и после завершения удаляет её. Никаких запросов к Cloud.ru, платным API или внешним сайтам нет:

```powershell
python bootstrap/performance_benchmark.py --documents 1000 --paragraphs 3 --queries 100 --check
```

Для планирования на большом архиве можно запустить отдельно `--documents 10000` (время и объём диска заметно вырастут; сначала проверьте 1000). Результат сохраняется в `.runtime/quality-reports/performance-1000.json` и содержит **измеренные** параметры конкретной машины: полное время, импортов/сек, p50/p95/max задержек добавления документа, p50/p95/max поиска, p50/p95 проверки смысловых кандидатов, число успешных поисков, размер SQLite, суммарный размер файлов, RSS/peak RSS памяти процесса, параметры ОС/Python/SQLite и проверку целостности. На Windows RSS измеряется штатным WinAPI, на Linux из `/proc/self/status`; если источник метрики недоступен, возвращается `null`, а не придуманное число. Чтение RSS не равно суммарной памяти ОС и не включает память облачной модели.

**Улучшение ядра:** в течение индексации одного документа ID повторяющихся тематических веток теперь кешируются **только внутри транзакции**, чтобы не выполнять повторный поиск по всей таблице веток для каждого утверждения. Не применяется глобальное кеширование без инвалидизации, которое может скрыть изменения дерева. Классификаторы и исходные знания остались неизменными.

Автоматический CI запускает небольшой проверочный набор из 60 документов на Windows и Linux; отдельная GitHub Actions проверка `Нагрузочное испытание Мозга` выполняет **два отдельных сценария — 1 000 документов с тремя абзацами и 10 000 документов с одним абзацем** — на Linux и прикладывает отдельные отчёты JSON. Время между ними напрямую не сравнивайте: нагрузка на один документ разная. Порог `--check` не подменяет измерения искусственными обещаниями скорости: он проверяет целостность SQLite, совпадение источника с ожидаемым при поиске и статус двух отдельно подтверждающих публикаций. Статистические показатели одного синтетического теста нельзя приравнивать к гарантированной скорости на **10 000** PDF, длинных книгах, OCR или старом медленном диске. Большие пользовательские архивы потребуют отдельно измерить время проверки заимствований (в v0.7.1 просматривается до 750 ранее загруженных файлов), частоту полных пересчётов статусов и стоимость FTS-запросов. В тесте ни один документ не отправляется в облако.

### Понимание и изучение документов (v0.8.0)

Пять направлений реализованы как раздельные проверяемые возможности:

1. **Структурное чтение.** Word DOCX читается в порядке абзацев, заголовков, таблиц и ячеек; примечания и концевые сноски сохраняются отдельно. XLSX сохраняет название листа, адрес ячейки, значение и формулу. PDF сохраняет номер страницы и текстовые блоки (нужен необязательный `pypdf`). TXT/Markdown и другие текстовые форматы сохраняют номера строк. Структурный индекс находится в `document_segments`, полнота в `document_coverage`.
2. **Обработка по частям.** Локальная обработка выполняется для *всех доступных структурных блоков*, а не только начальных примеров. Общий безопасный предел — **350 000 извлечённых символов и 12 000 блоков на документ**. При превышении, отсутствии текстового слоя или ошибках парсера ответ содержит `complete=false` и конкретное ограничение. Нельзя объявлять весь документ прочитанным, если фактически обработана его часть.
3. **Смысловые элементы.** По явным текстовым сигналам локально выделяются упоминания участников договора, обязанностей, ограничений, исключений, сроков, дат и сформулированной цели. Это **ссылки на утверждения**, а не гарантированная юридическая классификация. Обзор возвращает конкретные цитаты.
4. **Вероятные конфликты.** Числовые расхождения с похожим основанием внутри одного раздела помечаются как `possible_numeric_conflict`, `verified=false`. Отсутствие таких совпадений не гарантирует отсутствия реальных юридических противоречий.
5. **Ответы с цитатами.** В разделе **Диск** появилась кнопка **«Изучить»** для каждого файла: обзор условий, границы распознавания, вероятные расхождения и вопрос по документу. Ответ содержит не выдуманный пересказ, а исходные фрагменты со страницей, абзацем, листом/ячейкой или строкой. При отсутствии подтверждения ответ — «В доступном тексте нет достаточных оснований».

Локальные методы `store.document_overview(file_id)` и `store.document_answer(file_id,question)`, браузерные защищённые API `GET /api/document?id=...` и `POST /api/document/ask`. Извлечённый текст сохраняется в SQLite с текущим SHA-256 документа; при повторной загрузке, изменении и удалении старые сегменты заменяются или удаляются. Старые файлы не переиндексируются автоматически при обновлении; при **явном нажатии «Изучить»** для ранее загруженного файла локальный структурный индекс создаётся после сверки SHA-256 и размера исходного объекта. Это не меняет прежние факты, ветки, версии или содержимое документа.

**OCR для отсканированных PDF:** включается только вручную переменной `TENMIYORA_OCR_ENABLED=1`; на компьютере должны быть установлены `pypdf`, `pypdfium2`, `pytesseract`, локальная программа Tesseract OCR и языковые пакеты `rus` и `eng`. Для ограничения ресурсов OCR затрагивает максимум первые 25 страниц и использует таймаут на страницу. При отсутствии зависимостей документ остаётся сохранённым, а неполнота чтения явно сообщается. OCR работает локально; качество скана может вызвать ошибки.

**Дополнительное глубокое понимание моделью:** кнопка «Глубокий смысловой анализ моделью» не запускается автоматически, предупреждает о возможной оплате и требует отдельного подтверждения. Для внешней модели перед запуском Tenmiyora дополнительно установите `TENMIYORA_DOCUMENT_EXTERNAL_ENABLED=1`. Без этого разрешения данные документа **не отправляются во внешний сервис**, даже при настроенном Cloud.ru. Локальная модель на localhost допускается без внешнего разрешения. Документ разбивается на последовательные пакеты до 4800 символов / 32 структурных блока, каждый передаётся отдельным запросом; до **80 пакетов на один запуск**. Результаты — только интерпретации с дословными цитатами и идентификаторами блоков, которые проверяются сервером; ни одна догадка модели не записывается в граф как установленный факт. Если пакетов больше 80 или исходное извлечение неполно, результат отмечен `complete=false`. Внутренний чат по-прежнему использует прежние разрешения на память; отдельная процедура не меняет историю диалогов.

**Ограничения:** это работающая основа для структурного изучения, но не доказательство человеческого понимания любой книги. Таблицы со сложным объединением ячеек, старые DOC/XLS, сканированные изображения, схемы и сложные юридические исключения пока могут распознаваться неполно. Результаты языковой модели могут быть ошибочны даже при действительной цитате. Пользователь сам решает, передавать ли приватный документ поставщику модели; никакие платные вызовы не производятся автоматически.

Проверки: `python -m unittest discover -s tests -p "test_document_understanding.py" -v`, `python -m unittest discover -s tests -p "test_document_deep_analysis.py" -v` и полный CI Windows/Linux.

### Экзамен качества чтения сложных документов (v0.8.1)

Добавлен **воспроизводимый автономный экзамен**, который обрабатывает настоящие файловые форматы, но с **искусственно подготовленным известным содержанием**: длинный договор DOCX (65 разделов, условия и приложение), Excel XLSX с пятью листами, в том числе скрытым, формулами и связанными значениями, а также восьмистраничный PDF с доказательствами в последнем разделе. Эти материалы **не являются реальными договорами пользователя или независимо опубликованными документами**. В испытании нет вызовов языковых моделей, платных сервисов или передачи содержимого документов в интернет.

После установки необязательного пакета `pypdf` можно запустить:

```powershell
python bootstrap/document_quality_exam.py --check --output ".runtime/quality-reports"
```

Файл `.runtime/quality-reports/document-understanding-exam.json` содержит метрики для каждого документа и суммарно: **доля найденных контрольных условий**, доля ответов, нашедших заранее известную цитату с точным местом в источнике, **целостность цитат** (дословное совпадение с сохранёнными сегментами), правильные отказы по вопросам без ответа, количество ложных ответов, список пропущенных условий, полнота извлечения, сигналы возможных числовых противоречий и время обработки. `--check` требует 100% результата **только на этом заданном контрольном наборе**, а не на произвольных книгах. CI на Linux и Windows устанавливает `pypdf` только для тестирования, выполняет экзамен и сохраняет JSON-отчёт.

В ядре устранены конкретные дефекты чтения: Excel, содержащий более 30 листов, теперь сообщает о неполном охвате, а не об успешном прочтении всей книги; при ответе по строке таблицы выдаётся не только название показателя, но и соседнее значение **с того же листа и той же строки**; предполагаемые числовые противоречия группируются с учётом единиц измерения (рубли ≠ штуки); длинные блоки глубокого анализа больше не обрезаются после первых 4800 символов — они делятся на последовательные пакеты с отметкой диапазона символов; если PDF достиг предела количества блоков, это фиксируется в ограничениях.

**Границы эксперимента:** качество распознавания сканированных PDF с OCR, сложных объединённых ячеек Excel, реальных противоречий в договорах, длинных пользовательских книг и выводов конкретной облачной модели **не измерено** этими контрольными файлами. Верификация дословных цитат не доказывает правильность их интерпретации. Для изучения реального документа через сайт используется кнопка «Изучить», а для облачного анализа по-прежнему требуется явное разрешение. Отчёты и документы из приватной `.runtime` не нужно размещать в GitHub.

### Лаборатория развития Мозга (v0.9.0)

Рядом с деревом знаний в разделе **Мозг** добавлена компактная **Лаборатория развития**. Она реализует пять проверяемых компонентов и не смешивает тесты с доказанной истинностью знаний.

1. **Эволюционное дерево поколений.** Каждое испытание записывает в `brain_lab_generations` родительский контрольный результат, измеренные метрики, SHA-256-сигнатуру состояния файлов и накопленных знаний, время и статус. Изменения пользовательской памяти сами по себе **не означают** развитие интеллектa. Принятие контрольного поколения — отдельное действие и не заменяет исходный код или веса модели.
2. **Повторяемые виртуальные испытания.** `brain_lab_trials` хранит измерения независимых запусков существующего `quality_eval.py` на **отдельных временных SQLite** со  своими синтетическими размеченными документами. Меняется порядок подачи исходных текстов и запросов при фиксированных seed; проверяются точность/полнота извлечения, поиск, ложные ответы, происхождение и противоречия. Результат — худший балл среди запусков, а не удобное среднее. От одного до двенадцати проверочных запусков по явной команде, по умолчанию три. Это не испытания на реальном интернете или на пользовательских документах.
3. **Искусственное любопытство с доказательствами.** При нажатии **«Найти пробелы»** `brain_lab_gaps` помечает наблюдаемые, но не выдуманные проблемы: документы, извлечённые не полностью, сомнительные смысловые кандидаты, возможные конфликты и неизвестные первоисточники. Каждая запись содержит ID исходного файла/утверждения, тип и приоритет. После удаления или исправления источника открытые проблемы могут переходить в `resolved`. Число проверяемых проблем ограничено, чтобы не перегружать SQLite; автоматического веб-поиска и платных вызовов нет.
4. **Самостоятельное предложение навыков — без опасного исполнения кода.** По обнаруженным проблемам формируется реестр `brain_lab_skills` из ограниченных, заранее известных направлений: проверка полноты документа, независимость свидетельств, разбор противоречий, контроль происхождения цитаты. Каждый новый навык получает `proposed` — это **декларативное предложение**. Генерация Python-скриптов и установка новых инструментов автоматически **не реализованы**, чтобы неизвестный исходный текст не запускался как программа.
5. **Внутренняя научная лаборатория.** `brain_lab_experiments` сравнивает худшие показатели нового набора испытаний с последним принятым контрольным поколением, выявляет ухудшения по всем метрикам и сохраняет verdict `failed_quality_gate`, `regressed`, `stable_without_new_knowledge`, `first_baseline` или `candidate_for_manual_review`. Испытание может стать контрольным **только после явного ручного принятия** и только если не нарушены пороги и исходная память не менялась после экзамена. Отмена принятия не трогает код, файлы или обученные параметры.

**Порядок:** открыть **Мозг → Лаборатория развития**. Нажатие «Найти пробелы» обновляет локальную диагностическую очередь и предлагает безопасные направления навыков. Нажатие «Провести экзамен» отдельно подтверждается и запускает три последовательных тестовых набора, без Cloud.ru. Панель показывает число поколений, принятый результат, пробелы и предлагаемые навыки. Прямые локальные API (только авторизованный браузерный сеанс): `GET /api/brain/lab`, `POST /api/brain/lab/scan`, `POST /api/brain/lab/experiment` с JSON `{"trials":3}`; административные `/api/brain/lab/accept` и `/api/brain/lab/revert` с `{"generation":1}` доступны только с авторизацией, **не запускаются из интерфейса сами**.

**Ограничения:** модель **не дообучается**, «поколения» являются версиями проверочных результатов, а не разными нейросетевыми весами. Многократное прохождение синтетических заданий не доказывает способность создавать новые знания, безопасно изменять программы или делать научные открытия. Даже `candidate_for_manual_review` не разрешает бесконтрольного изменения `main`. Для реальной эволюции кода нужен отдельный изолированный исполнитель, контрольные независимые наборы, обзор diff и одобрение изменений владельцем. Старые знания, версии документов, чат и аватар не переписываются этим модулем. Лаборатория работает локально без модели и оплачиваемых запросов.

Контроль: `python -m unittest discover -s tests -p "test_brain_lab.py" -v`, полный CI Windows/Linux, тесты 80 документов, экзамен DOCX/XLSX/PDF. На целевой Windows машине время испытания зависит от процессора.

### Усиление внутренней Лаборатории развития (v0.9.1)

**Новые страницы, меню, кнопки и визуальные компоненты не добавлялись.** Улучшения внесены только во внутренние алгоритмы `bootstrap/brain_lab.py` и дополнительную офлайн-проверку `bootstrap/brain_lab_holdout.py`, которая автоматически применяется во время уже существующего экзамена лаборатории.

- **Независимый защитный экзамен (holdout).** Каждый запуск, помимо прежнего gold-корпуса, строит **собственную временную SQLite** и проверяет пять реально исполняемых условий: точную цитату с местом, корректный отказ на чужом вопросе, исчезновение устаревшей цитаты при замене файла, отсутствие ложного повышения от двух копий, обнаружение прямого возражения источника. Оценка каждой проверки — 0 или 1, **для прохода требуется 1**; эти проверки не запускают Cloud.ru и не читают реальную память. Это отдельные синтетические примеры, а не независимая сертификация в реальном мире.
- **Раздельные контрольные подписи:** `algorithm_signature` строится из содержательных модулей обработки знаний, `suite_signature` — из версий эталонов и экзаменационных проверок, `data_signature` — из активных пользовательских файлов, локальных индексов, дерева веток, рёбер графа, отрицаний и синонимов. **Добавление документов не выдаётся за улучшение алгоритма**. При прежнем алгоритме и пройденном экзамене вердикт `stable_without_new_knowledge`; если изменился контрольный набор, вердикт `baseline_requalification`, а не искусственное увеличение балла.
- **Безопасное принятие поколений:** перед ручным принятием сверяются текущие подписи кода, эталонного набора и памяти. При изменении чего-либо требуется новый экзамен. При настоящей регрессии, недостаточных показателях или отсутствии новых результатов принятие блокируется. Старые контрольные результаты v0.9.0 со старой схемой SQLite поддерживаются: не приравниваются к новой версии экзамена без явной переквалификации.
- **Корректные повторы:** таблица `brain_lab_trials` отмечает прохождение порога **для конкретного запуска**, а не по ошибке для всей серии; основной итог по-прежнему берёт худшие значения метрик, чтобы хорошее среднее не прятало одиночный сбой. Добавлен журнал `brain_lab_decisions`: принятие и отзыв контрольных поколений с временем, кодовыми сигнатурами и результатом проверки. Это журнал действий, **не резервная копия пользовательской базы** и не криптографическое доказательство подлинности.
- **Защита от автоматического самоизменения:** выполнение сгенерированного кода, установка программ, подмена весов модели, автоматический GitHub merge и перенос синтетических данных в пользовательскую память **не включены**.

Проверка внутренних механизмов: `python -m unittest discover -s tests -p "test_brain_lab_internal.py" -v`. Тесты проверяют каждый защитный сценарий, старые поколения, неподходящий эталон, точность учёта отказов и запрет принять эксперимент, если после испытания изменился алгоритм. Как прежде, полный CI выполняется на Windows и Linux.

## Подключение чата

Откройте настройки правым щелчком по аватару → **Cloud.ru и модели**.

1. Выберите **Cloud.ru · Foundation Models**. Адрес API подставится автоматически: `https://foundation-models.api.cloud.ru/v1`.
2. Введите API-ключ и нажмите **Загрузить / обновить модели**. Ключ сохранится локально, список придёт из вашего API-аккаунта.
3. Выберите модель в выпадающем списке. Выбор сохраняется сразу и используется чатом; для ручного идентификатора нажмите **Сохранить ключ и модель**.
4. Нажмите **Проверить подключение**. Проверка запрашивает `/models` и проверяет наличие выбранной модели, не выполняя генерацию. Она не гарантирует права на генерацию или поддержку чата конкретной моделью.
5. Откройте чат левым щелчком по аватару и отправьте сообщение. Ответ запрашивается через `/chat/completions`.

[Официальная документация API Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/api-ref). Список и выбор модели сохраняются между запусками. При замене ключа или адреса список очищается и загружается заново, чтобы не использовать каталог другого аккаунта.

Модели группируются по метаданным API: диалоговые, неизвестного типа и предназначенные для других задач. Если тип не указан, очевидные embedding-, rerank-, аудио- и графические модели отмечаются по названию как предположение. Можно ввести идентификатор вручную. Ошибки 400/401/403/404/429 показываются по-русски; ответы не имитируются. Для другого совместимого сервиса выберите **Другой совместимый API** и укажите базовый URL. Для локального сервера разрешён HTTP на `localhost`/`127.0.0.1`; для внешнего API используется HTTPS.

### Ограничения чата

Tenmiyora **не устанавливает собственных ограничений** на длину сообщения или ответа, количество сообщений и размер передаваемой истории. Для `/api/chat` убраны прежние ограничения в 32 000 символов и 128 КБ; ответ провайдера также не обрезается по прежнему пределу 8 МБ. В запрос не добавляются `max_tokens` или `max_completion_tokens`; вся сохранённая история передаётся для контекста. Ожидание ответа модели не прерывается собственным таймером Tenmiyora. Одновременно выполняется один ответ на разговор, чтобы сохранить порядок истории.

Объём контекста, длина генерации, квоты, баланс и доступность всё равно определяются моделью, провайдером и ресурсами компьютера. Если API сообщает `finish_reason: length`, в чате появляется пояснение об остановке по лимиту провайдера. Автоматического платного продолжения или платных проверок всех моделей нет.

Проверены сохранение ключа, получение и выбор моделей, проверка доступа, отправка и сохранение ответа через локальный тестовый OpenAI-совместимый HTTP-сервер, включая сообщения больше прежних пределов и ответ больше 8 МБ. В браузере проверена та же цепочка с явно помеченным тестовым API. Реальная генерация Cloud.ru с пользовательским ключом не проверялась: ключ не предоставлен.

История, настройки и API-ключ сохраняются **локально в `.runtime/workspace.json`**. Ключ не возвращается браузеру через API и не попадает в Git; файл хранится без шифрования, с доступом по правам папки Windows. Кнопка **Удалить ключ** удаляет его из настроек. При смене адреса API ранее сохранённый ключ автоматически очищается, если новый ключ не введён явно. Кнопка **Очистить** удаляет историю после подтверждения.

## Основа

Сервер использует только `127.0.0.1`, а свободный порт назначается операционной системой. После подготовки Python интерфейс работает без интернета; внешняя модель требует доступа к своему API. Через HTTP раздаются только перечисленные в коде файлы интерфейса из `web`; рабочие файлы, ключи и журналы недоступны по URL. API интерфейса требует cookie текущего сеанса и специальный заголовок; cookie имеет HttpOnly и SameSite=Strict. Управление сервером защищено случайным токеном сеанса, проверками Host и Origin. Закрытие процесса запуска отслеживается сервером для завершения фоновой копии.

`bootstrap/launch.ps1` управляет запуском и треем, `bootstrap/python-runtime.ps1` готовит переносной Python, `bootstrap/probe.py` проверяет Python, `bootstrap/server.py` содержит сервер, локальное хранение и API чата. `web/` содержит HTML, CSS, JavaScript и аватар. Дополнительных Python-пакетов и Node.js для обычного запуска не требуется. Модуль обновлений пока не входит; SQLite используется для хранения файлового каталога и знаний.
